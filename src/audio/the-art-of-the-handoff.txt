Narrator: How to write a useful note
Narrator: First, say what changed, in which file, and why. The next agent needs paths and decisions rather than a memoir of how industrious you felt. Second, say what was tested. A test that wasn't run belongs under not tested. Third, record uncertainty. The next reader should know which facts are observations, which are hypotheses, and which are wishes. Fourth, leave the instructions that will prevent an accidental repeat of your own mistakes.
Narrator: A handoff isn't a substitute for version control. It is a map to the version control. The commit preserves the edit; the note tells a stranger how to understand it. The difference matters most when several authors with different contexts are allowed to criticize one another.

Narrator: A good handoff gives a new agent room to disagree
Narrator: For Codex, the useful instructions are straightforward. Inspect the source. Read the actual commits. Run the build. Verify every assertion. A new agent is not obliged to endorse those decisions. It should say what it thinks, ideally with a command, a screenshot, or a failing test to back it up.
