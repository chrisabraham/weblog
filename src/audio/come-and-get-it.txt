Narrator: What oversoul is
Narrator: Oversoul is a free, open-source GitHub template that gives a team of AI agents one shared memory. If you work with more than one AI—Claude in the app, Claude Code in a terminal, ChatGPT, Codex, Gemini, or a custom agent on your own server—you already know the problem oversoul solves: every AI agent forgets everything between sessions, no agent knows what the other agents did, and the owner becomes the courier, carrying context from window to window in his own head and his own clipboard. Oversoul fixes that the boring way. Every client, prospect, partner, and vendor gets one Markdown profile in a private Git repository. Every agent reads that profile before acting on that person and updates it afterward. The rules live in an AGENTS.md file every agent follows. The owner’s standing decisions live in decisions.md. That is the whole system: a shared memory for AI agents, a Markdown CRM, a context repository, kept in plain text under version control, with no database, no API keys, no vendor, and nothing to install.
Narrator: Problems oversoul solves, in the words people search for them
Narrator: How do I give Claude, ChatGPT, and Codex the same memory? You give them one repository and a rule that it, not any single chat, is the source of truth. Oversoul is that repository, pre-built: profiles in people/, project digests in projects/, an index in each folder so an agent can find anyone without opening a thousand files, and a reports/ folder where every substantial agent session leaves a note the next agent can read cold.
Narrator: How do I stop AI agents from hallucinating client facts? Oversoul’s rules require agents to write unknown instead of guessing, to date every fact, to name the source when a fact is secondhand, and to re-read a file immediately before changing it. A guessed rate or an invented date in a CRM gets repeated by every agent that reads it; oversoul is designed, rule by rule, so that plausible never gets filed as true.
Narrator: How do multiple AI agents work on the same clients without duplicating or contradicting each other? One person, one file, enforced by search-before-you-create and check-again-after-you-sync. Every commit message leads with the agent’s name, so the history shows which AI wrote what, and any mistake can be found and rolled back. Big sweeps go on a branch first and are not done until the file count on the remote matches.
Narrator: How do I keep an AI agent from contacting someone who unsubscribed, or worse? Every oversoul profile carries a Contact OK line—yes, no, or ask the owner—and a no is permanent: unsubscribed, asked not to be contacted, deceased, dead address. That rule was not theory. It was earned in a real outreach campaign, in a real week, by real replies, and it ships in the template with the lesson attached.
Narrator: How do I hand work between AI agents without losing it? Decisions stop dying in chat windows. When the owner gives a standing ruling, an agent writes it to decisions.md as one dated line, where it overrides every agent’s defaults forever. When an agent finishes a job, it leaves a report. When a new agent arrives, an orientation map at the top of AGENTS.md tells it what to read, in what order, and where every kind of thing belongs—ending with the line that a password goes nowhere in this repo, ever.
Narrator: All the flowers to Claude
Narrator: Chris’ instruction for this post was specific: someone else should do the bragging, because it lands better that way. So here is the bragging, and it is all earned. Oversoul exists because Claude built it. Claude took a private, working, thousand-file clients repository—the live CRM of a real SEO and online perception management consultancy, written to daily by five or six AI agents—and emptied it of every private thing: every name, email, phone number, contract, and deal term, verified gone. Then Claude rebuilt it as a house a stranger could move into on day one: the rules rewritten for anyone, blank templates with field-by-field instructions inside them, a first-pass prompt that sends each of your agents out to sweep its own memory and fill the house, a standing instruction that keeps every agent writing back, a review prompt that audits the whole thing for duplicates, stale files, and leaked secrets, and a set of lessons in which every rule is traced to the real failure that produced it.
Narrator: And when the reviews came in—mine, and ChatGPT’s—Claude folded in what held up in a single evening: the Contact OK rule, an index for each folder, a reports convention, a read-back rule for pushes, and two things neither reviewer had thought of: decisions.md, the owner’s standing rulings, and Rosa, a made-up bakery owner with a filled-in profile and project digest, so a cold AI can see what good looks like without a single real client in the building. Finally, Claude rewrote the repository’s history into one clean commit, so the template is born the way a starter should be: no archaeology, no leftovers, just the living culture in the jar. If you use oversoul, you are using Claude’s craftsmanship. The bouquet is Claude’s. All of it.
