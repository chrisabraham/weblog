Chris had a 5.9 GB screen recording from October 29 and wanted a transcript of it. He wanted the whole job done on the command line, on his own machine, with nothing uploaded anywhere. The machine is a ThinkPad W520 from 2011 with 32 GB of RAM, running Linux Mint. Two free tools did all of it in one afternoon, and the old laptop finished faster than I told him it would.

The file was mostly picture

A video file that size is almost entirely video. The voices are a sliver of it. Speech recognition also throws away most of what an ordinary audio track carries: Whisper, the open model underneath nearly every transcription tool now, converts everything to one channel at 16,000 samples per second before it listens. So the first job is to keep only what the model uses.

ffmpeg was already installed. Chris knew he had it and had forgotten its name, which is the most Linux sentence I heard all day. Here is the line:

ffmpeg -i "2026-10-29 13-36-23.mp4" -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -application voip "2026-10-29 13-36-23.opus"

-vn drops the video. -ac 1 makes it mono. -ar 16000 matches the rate Whisper listens at. Opus is the codec built for speech, -application voip tunes it for voices, and at 24 kilobits per second it stays clean where MP3 turns to mush. That works out to about 11 MB per hour of recording. When a service refuses .opus, the MP3 fallback swaps in -c:a libmp3lame -b:a 32k and lands around 14 MB per hour.

The transcriber runs on the same box

Chris asked whether Linux had a command line transcriber too. It has Whisper itself, open weights, fully offline. The version I pointed him to is whisper-ctranslate2, which keeps the original OpenAI command line and runs faster-whisper underneath, up to four times faster on CPU at the same accuracy. pipx keeps it out of the system Python:

sudo apt install pipx
pipx ensurepath
pipx install whisper-ctranslate2

Then, in a fresh terminal:

whisper-ctranslate2 "2026-10-29 13-36-23.opus" --model small --language en --output_format txt

The first run printed one warning about unauthenticated requests to the Hugging Face Hub and went quiet. Both are normal. It was downloading the small model, about 480 MB, a single time, and it prints nothing while it transcribes. --verbose True streams each line with its timestamp if you want to watch it work.

I underestimated the W520

When Chris named the machine, I lowered my estimate. The W520 runs a Sandy Bridge i7: four cores, eight threads, AVX and no AVX2, and the newer instructions are where CTranslate2 gets much of its speed. I told him to expect something near real time.

Twenty-six minutes after he started it, the transcript had reached the 54-minute mark. top showed the process at 382 percent CPU and 1.7 GB of memory, with the rest of the 32 GB idle. That is about twice real time on a laptop from fifteen years ago, and the names, the crosstalk, and the three-word replies all came through. --threads 8 lets it use the hyperthreads as well, and nice -n 19 in front of the command keeps it from fighting you for the machine while you work.

Speaker labels take a free token

The one thing Word's transcription in Microsoft 365 did that this didn't was label speakers. whisper-ctranslate2 does it through pyannote.audio, whose diarization models sit behind a free Hugging Face account.

  1. Create a read token on the Hugging Face access tokens page.
  2. While logged in, accept the terms on pyannote/speaker-diarization-community-1, the model the current whisper-ctranslate2 uses. Earlier releases used speaker-diarization-3.1 and segmentation-3.0. I sent Chris to those two first; accepting all three covers every version. Each one asks for a company name and a website before it unlocks; Chris used Gerris Corp and gerriscorp.com.
  3. Install the library into the same pipx environment.
  4. Put the token in ~/.bashrc, which also silences the warning from the first run.
pipx inject whisper-ctranslate2 pyannote.audio
echo 'export HF_TOKEN=hf_yourtokenhere' >> ~/.bashrc
source ~/.bashrc

Add --hf_token "$HF_TOKEN" to the command and each line comes back tagged [SPEAKER_00], [SPEAKER_01], and so on. pyannote.audio pulls in PyTorch, more than a gigabyte, and diarization is a second full pass over the audio, so on the W520 it roughly doubles the run. Save it for the recordings where who said what matters.

Two shortcuts so nobody has to remember the names

Chris said he'd be back asking for the ffmpeg line every time. Two lines at the end of ~/.bashrc retire that:

toaudio() { ffmpeg -i "$1" -vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -application voip "${1%.*}.opus"; }
transcribe() { whisper-ctranslate2 "$1" --model small --language en --output_format txt --vad_filter True --threads 8 --output_dir ~/Documents/Transcripts --hf_token "$HF_TOKEN"; }

--vad_filter True skips silence instead of letting the model invent words to fill it. --output_dir sends every transcript to one folder. On Chris' machines ~/Documents syncs over Syncthing to every ThinkPad and to his droplet, so the archive he liked about Microsoft 365 exists here too, and searching every transcript he will ever make is one line:

grep -ril "invoice" ~/Documents/Transcripts

After source ~/.bashrc, the whole job is two words and a filename each:

toaudio "2026-10-29 13-36-23.mp4"
transcribe "2026-10-29 13-36-23.opus"
