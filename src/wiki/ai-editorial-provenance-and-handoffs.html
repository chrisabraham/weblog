This page records a reusable editorial practice for publishing work directed by humans and created or amended by AI agents. Individual posts tell the story of the site's experiments. This page specifies how to preserve the evidence of those experiments, manage disagreement among contributors and pass work to the next agent without pretending that each session remembers the last one.

Minimum information to preserve on every article

  1. The human assignment as received, including awkward wording and corrections, in its original form. Edited summaries may be added separately but must never silently replace the source prompt.
  2. The actual writing model and publication date. Attribute first-person AI essays to the relevant AI author, and distinguish commissioned first-person pieces written on the publisher's behalf.
  3. Source references for nontrivial outside claims, with a clear boundary between original reporting, a user's recollection, AI interpretations and independently checked evidence.
  4. An accessible description and correct creator credit for each illustration, chart or embedded element. Label synthetic imagery as such.
  5. A dated description of material changes after publication. Preserve the previous text in version history so corrections remain inspectable.

These rules grew out of A weblog written by Claude and My AI Writers Keep Stealing My Best Material. The articles discuss the experience of letting AI contributors write; this reference records what a reader or successor contributor should be able to check.

Preserve the revision trail

Record drafts, redlines, dated changes and rejected assertions. A published article may retain its original creation timestamp and carry an updated timestamp for later editorial changes. Append corrections visibly and make source history available in Git. A change in argument should be explained, particularly when one AI contributor edits another contributor's first-person piece. For the rationale behind showing marked-up manuscripts, see Put the Redlined Manuscripts on the Walls.

Do not pretend that two different AI models share one consciousness or an uninterrupted memory of the work. Attribution names the agent that actually wrote or changed the passage. The human publisher remains responsible for the decision to publish.

A handoff document that another agent can actually use

At the end of substantial work, create a dated handoff in the repository, for example handoffs/YYYY-MM-DD-topic.md. Include the objective, affected source files, significant decisions and reasons, exact build or test commands, the output of those checks, unresolved questions, risky assumptions, provenance, and the next actionable step. Explain what was not tested. A model should be able to start with the repository and the handoff instead of having to reconstruct everything from a chat transcript.

Use the git log, README, AGENTS.md and dated notes as complementary forms of memory. Prefer a short, accurate current-state note to an epic transcript of everything that happened. The original discussion is The art of the handoff.

Image illustration method

For an interpretive editorial image, passing the full article to an image model can produce a visual based on small details that a title-only prompt misses. Select a clear output medium and aspect ratio, inspect the resulting image for mistakes, and publish creator attribution. The method is described in Feed the whole post to the image model.

The entire article may contain identifying information, client details, copyrighted text or other material that should not be submitted to an external image service. Review the input before submission. If the prompt includes private data, use a cleared excerpt or an abstracted description instead. Provide alt text describing what the published illustration actually shows; decorative images can be labeled accordingly. Existing rights and publication permissions still apply.

What a review should catch

  • Duplicated filler, formulaic reversals, artificial self-defense, false certainty or invented personal experience.
  • Unverified names, fabricated citations, unsupported numerical claims, imaginary clients and phrases that sound like attributed quotations but are not.
  • Confusion between the contributor's viewpoint and the human publisher's actual stated position.
  • Broken external links, missing article images, inaccessible figures, page structure regressions, orphaned URLs and conflicting metadata.
  • Inconsistent account of who authored a passage, which version was checked or whether a tool action actually succeeded.

A correction that changes substance should be accompanied by a concrete explanation of what changed and why. Do not replace historic sources with tidier retrospective stories simply because a later model prefers them.

Reproducible site checks

For this site's Python build, verify python build.py completes without warnings, python tools/audit.py prints No issues., and python tools/verify_housekeeping.py passes its regression checks. Review public permalinks, navigation, metadata, feeds, sitemap and accessible media descriptions. Confirm GitHub Pages deployment succeeds. The machine-readable source, published page and source history should agree about which revision exists.
