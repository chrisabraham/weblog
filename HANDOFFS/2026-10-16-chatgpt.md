## Findings from public source inspection

1. The source index renderer formerly included the full bodies (and potentially media) of fifteen articles. Chris identified that as a too-long scroll. The source now uses one existing `description` paragraph plus a clearly labeled link per article, and leaves every full article at its permanent URL. This also applies to monthly archive summaries. Full canonical articles retain their prompts, existing media and historical annotations.
2. Two real CSS-cascade bugs: the skip-link focus style could yield paper-colored text on paper; global focus against top navigation could yield the same blue foreground and background. Both were 1:1 contrast by code inspection, in light/dark modes. CSS now explicitly sets foreground and background for those states and adds visible focus outlines.
3. Palette computation from source: existing blue-on-paper contrast approximately 9.92:1 light and 8.31:1 dark. The orange is approximately 4.59:1 light and 7.57:1 dark. Existing blue should be preserved; the issue was the interactive focus cascade.
4. Source colophon described Georgia as the reading font, but CSS assigns Verdana. Corrected colophon to match the actual stylesheet.
5. An article used wiki-style `[[Little boats, one flotilla|flotilla]]`, which rendered as a wiki redlink to the wiki landing page, even though the full article exists. The generator now resolves wiki syntax matching article titles to their existing canonical article URLs. No published prose was silently rewritten.
6. The original repo's built-in audit script is a static crawler, not a browser/WCAG certification. Its earlier claims about 100-point Lighthouse results are historic claims by previous authors, not tests run by ChatGPT.

## Architectural decisions

- Use the existing generator and CSS. Do not hand-edit `docs/` since `build.py` deletes and recreates generated output.
- Use a plain description as the teaser. An automatically stripped arbitrary HTML slice might break elements or excerpt the wrong material (e.g. a complex diagram, disclosure, or editorial note).
- No unnecessary tracking, external CSS, fonts, or dependencies.
- Semantic `BlogPosting`, `ProfilePage`, date/time, and proper credited authors. Only add schema that can be defended with the visible document and citations.
- Inline SVG illustrations are intentionally tiny in transfer size, with meaningful `title` and `desc`. A real picture asset can be added later if it produces a demonstrably better result for the visual budget.
- Existing large JPEGs have responsive source sets. A future reproducible pipeline could benchmark tasteful lossy WebP/AVIF conversions and retain copies only when visually justified, but no existing image has been re-encoded or misrepresented by this shift.
