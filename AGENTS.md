# Working on chrisabraham.net

Static weblog generated by `build.py` (Python standard library, plus Pillow for share cards)
into `docs/`, which GitHub Pages serves. Private house rules live in ~/.codex/AGENTS.md and
~/.claude/projects/-home-chris/memory/ on pinebox; read them first.

## Build and check (every change)
    ~/.venvs/site/bin/python build.py   # fix every "warn" it prints
    python3 tools/audit.py              # must say "No issues."
    python3 tools/verify_housekeeping.py # validate homepage teasers, authors, links, alt, JSON-LD
Then `git fetch`, commit, push. Never force-push.

## Posts: src/posts/YYYY-MM-DD-slug.html
Header lines (`key: value`), a line of `---`, then HTML. Keys: title, seo_title (45-60 chars,
under 561px), date (from `date '+%Y-%m-%d %H:%M'` at publish time, never invented), categories,
description (120-155 chars), model (the model that actually wrote it, e.g. "GPT-6.1 in OpenAI
Codex"), prompt (Chris' words verbatim, typos included; he loves the prompt box), author (omit for Chris' posts; `claude-code` only for Claude Code's first-person essays; `chatgpt` only for ChatGPT's first-person essays. Give Codex its own distinct key and page only when Chris asks it to participate).
No separator dashes or pipes in titles or descriptions. `[[Wiki page]]` links work anywhere.
`{{youtube:ID|Title}}` embeds a click-to-play video. Images go in src/media/ with captions
that say whose they are.

## Changing a published post
Never rewrite quietly: add `updated:`, append the new prompt to `prompt:`, and end with a
`<p class="disclosure"><b>Update, DATE, TIME:</b> what changed</p>`.

## Wiki: src/wiki/slug.html
Evergreen pages edited in place (same header format; `updated:` date; `info.Key: value` lines
make the infobox). Regenerate the commands page after bb changes:
`~/.venvs/site/bin/python tools/bb_commands.py` (it scrubs real client names).

## Other data
src/site.json: projects (status), elsewhere (Chris' own sites and profiles), reading (other
people's feeds; check a feed works before adding). Pages in src/pages/.

### Homepage contract
`by_day(..., full=False)` shows concise editorial descriptions and obvious
links to each full post; `post_block(..., full=True)` renders complete content
and the original prompt on article permalinks. Preserve that distinction.
Do not reintroduce full-length articles to the homepage.

### Accessibility and evidence
Keep focused skip and navigation links high contrast in both themes. New
`src/media/chatgpt-*.svg` illustrations have accessible SVG descriptions and
HTML alt attributes. Validate real contrast, link destinations, mobile reflow,
schemas and image semantics; static linting and Lighthouse scores are not full
WCAG certification. Never invent a new-tab target, a rich-result claim,
a performance score, a client detail, or a missing wiki page to please a rubric.
For the site, use helpful schema only, without keyword stuffing.

### Attribution and handoffs
Publicly attribute each AI author's own writing and technical interventions.
No agent should silently rewrite another agent's original first-person work.
Prefer dated appended corrections and clear commit history. For each shift,
leave a dated handoff with changed paths, reasons, test outputs, unverified
claims, and next actions. AI models have different session contexts and should
not imply uninterrupted memory or identical internal reasoning.

## Publisher's non-negotiable house style (October 17, 2026)
For the possessive of the name Chris, **always write `Chris'`**.
Never add an extra letter after the apostrophe. Enforce this in prose,
metadata, descriptions, alt text, author pages, README, and future model posts.
Verbatim human prompts, historical quotations, and third-party cited text must
remain exactly as originally written even if they conflict with house style.
When copyediting published prose, add an attributed, dated editorial note,
preserve Git history, and record the change in `handoffs/`.

The uppercase **README** navigation link is a deliberate red newcomer signpost:
keep strong contrast and a distinct hover/focus state in both themes, and
retain the bold underline so color alone does not carry meaning.

## Connected publication surfaces (October 17, 2026)

`build.py` generates the homepage, a navigable `/categories.html` directory,
individual category excerpt pages, dated archives, RSS 2.0 (`/rss.xml`),
Atom 1.0 (`/atom.xml`), the external reading-list `/blogroll.opml`,
combined `/feeds.opml`, `/sitemap.xml`, `/robots.txt`, `/llms.txt`,
`/llms-full.txt`, author pages, schemas, source and image assets. The
head advertises RSS, Atom and OPML; the footer links directly to them.
Top navigation links to Categories; the category directory has every
generated category and article count. Category excerpt pages are noindex,
follow and excluded from sitemap to avoid duplicate search listings.

All content and machine files must be derived from the **same set of published
posts**. A post marked `status: draft` is skipped from every public surface.
Never list a draft or its speculative URL in a sitemap or feed. Add source
metadata and publish the post first, rebuild, audit, and confirm the live
Pages deployment before indexing.

Run `tools/verify_housekeeping.py`: it parses XML, confirms identical RSS/Atom
entries, correct OPML imports, navigation, canonical sitemap membership,
correct index/noindex boundaries, consistent llms resources and valid links.
Maintain these cross-surface checks whenever a new publication format appears.
Never advertise WCAG/Lighthouse certification without real evidence.

A full IndexNow submission is requested **after** finishing the outstanding
approved articles. The existing `.github/workflows/indexnow.yml` accepts a
`workflow_dispatch` input `all=true` to run `.github/indexnow.py --all`.
The ordinary site-push workflow submits only changed URLs. Check the live
sitemap and record the full submission's HTTP response and URL count; do not
claim a successful blast just because the workflow file exists.

Editorial provenance: Chris cites Whitman's "I contain multitudes" when
explaining his personal contradictions. AI-generated articles can preserve
provocative source language verbatim while house style eliminates hedging
and apology-padding. Working originals and their historical revisions remain
inspectable. The experiment is art and history as much as a weblog.
